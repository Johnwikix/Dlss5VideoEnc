# 图片输入支持(复用现有 NR 基础设施)

## Context

调研已实证 DLSS NR 可用于单张图片(单帧 `reset=1` 是模型合法路径,效果≈视频稳态)。本任务给工具添加图片输入:PNG/JPEG 等静态图 → NR 单帧增强 → PNG/JPEG 输出。设计原则是**最大化复用**:图片走 `DlssVideoPipeline.RunAsync` 同一入口,CLI / GUI 队列 / `--autorun` 三个前端零结构改动即获得图片支持;NGX 会话生命周期沿用现有"每输入一会话 + PipelineGate 串行"模式(同进程多会话已被批量视频验证)。

## 核心架构决策

1. **分派点**:`DlssVideoPipeline.RunAsync` 在 `PipelineGate` 内按扩展名分派到新的 `RunStillImageAsync`(partial 新文件),视频路径完全不动。
2. **tiling 恒开**:图片会话始终 `dlssnr_configure_tiling(1, 6000, 3000)`(宿主默认 tile)。宿主 tiled 路径专为静态图设计——每 tile 独立 reset=1、raised-cosine 重叠混合;小于 tile 的图自动退化为单 tile 全帧评估(无质量差异),超过 6000×3000 的大图自动分块,零特判。
3. **单帧语义**:强制 `DlssNrOptions { ContinuousHistory=false, TemporalStabilization=false, MotionGuidance=false, UseGpuTemporalProcessing=false, FineMotion=false }`,不用 GpuNrProcessor/异步队列/光流——纯 CPU `ProcessFrame(byte*, byte*, reset:true)` 路径(零 guidance fast path)。
4. **alpha 保留**:NR 前抽出 A 通道、RGB 按 alpha=255 送入;NR 后合回(PNG 输出保留透明,JPEG 丢弃)。
5. **输出格式**:默认 PNG(无损);`--output` 扩展名或 `--image-format jpg|png` 可选( jpg 用 `--quality` 映射 qscale)。JPEG 遇奇数尺寸自动回退 PNG + 日志说明。
6. **首版只做 NR**:图片输入忽略 interpolation/VSR/补帧 flag(日志提示);HDR/16bit 输入经 swscale 落到 8bit SDR sRGB(模型契约),不做 HDR 图片路径。

## 文件改动清单

### 新增

**`src/Dlss5Demo.Core/StillImageCodec.cs`**(~200 行)
- `static class StillImage`:`HashSet<string> Extensions = {".png",".jpg",".jpeg",".webp",".bmp",".tif",".tiff"}`、`IsImageFile(path)`。
- `static (int W, int H) Probe(string path)` / `static byte[] DecodeRgba(string path)`:`avformat_open_input` → 最佳视频流(图片=单帧流)→ 软件 `avcodec` 解码一帧 → `sws_getCachedContext` → 紧凑 RGBA8 `byte[]`。软件解码即可(mjpeg 虽 NVDEC 可用但无必要)。模式参考 `DlssVideoPipeline.Decoder.cs` 的 `NativeVideo.Check`/资源释放写法,但不用 avfilter/NVDEC/色彩标签。
- `static void Encode(string path, ReadOnlySpan<byte> rgba, int w, int h, string format, int quality)`:`avcodec_find_encoder("png")`(pix_fmt `rgba`/`rgb24`,`compression_level`)+ `"mjpeg"`(`yuvj420p` 偶数/`yuvj444p` 奇数,`AV_CODEC_FLAG_QSCALE` + `global_quality = quality * FF_QP2LAMBDA`),单帧 send/receive,packet 直写文件(不需 muxer)。sws 做 RGBA8→目标格式转换。

**`src/Dlss5Demo.Core/DlssVideoPipeline.Still.cs`**(partial,~150 行)
- `static async Task<TranscodeResult> RunStillImageAsync(input, output, options, progress, ct)`:
  1. `StillImage.Probe` → 尺寸;校验 `1..16384`(D3D12 纹理上限)。
  2. 忽略不适用功能并 `PipelineLog.Info` 提示(插帧/超分/HDR)。
  3. `OutputFileNames.Reserve(output)`(复用,扩展名无关)。
  4. `StillImage.DecodeRgba` → 抽 alpha(`byte[]? alpha`,纯 C# 每 4 字节)。
  5. `DlssNrHost.Create(HostDllPath, RuntimeDllPath, LogPath, w, h, 单帧选项, hdr:false)`(Create 新增 tiling 参数,见下)→ 固定/非固定 `NativeMemory.Alloc` 输入输出缓冲或复用 `VideoFrameSlot` 模式——单帧直接 `GCHandle` pin `byte[]` 即可(`ProcessFrame(byte*, byte*, true)`)。
  6. NR 后合回 alpha(保留)→ 按输出扩展名 `StillImage.Encode`。
  7. `options.PreviewSink?.Publish(source, w, h, processed, w, h, 1, 1, 0)` 一次(GUI before/after 预览免费获得)。
  8. `progress.Report((1, 1, 0))`;返回 `TranscodeResult { FramesProcessed=1, ... }`。
  9. 异常/取消语义与 `RunCoreAsync` 一致(取消→OCE);`PipelineLog` 埋点"图片管线开始/完成/失败"。

**`tests/Dlss5Demo.Tests/Program.cs`**

## 验证计划

1. `dotnet build` 全解决方案(x64)。
2. 无 GPU 回归:`dotnet run --project tests/Dlss5Demo.Tests -c Release`(现有 24 项 + 新 codec 往返项全绿)。
3. GPU 集成(用 `.tmp_still\cand_3.png` 2560×1440 暗帧):
   - `tests --image cand_3.png` → 输出 PNG,PSNR 25~45dB,视觉抽查(参照已有 crop 拼图方法);
   - **tiling 等价性**:用 ffmpeg 把图放大到 7000×4600(必然分块)跑通;另将一张 2000×1000 小图分别以"tiled 强制"与默认跑,输出 PSNR>50dB 验证单 tile 无损混合;
   - **alpha 往返**:合成半透明 PNG → 处理 → 输出 alpha 逐字节不变;
   - **与视频基线对照**:同图经"静止视频+`--continuous-history 0`"视频路径首帧 vs 图片路径输出,PSNR 量级一致(允许编码往返差异,不要求逐字节)。
4. CLI 批量:混合目录(视频×2 + 图片×2)一次跑完,输出命名/退出码正确;`--image-format jpg` 奇数尺寸自动回退 PNG。
5. GUI:`--autorun cand_3.png out.png` 无头验收(自动继承图片路径),GUI 手动验收留用户。

## 边界与不做

- 不做:图片超分(VSR)/插帧/HDR 图片路径/EXR/ICC 色彩管理;批图同尺寸会话复用(每图独立会话,与批量视频语义一致;`dlssnr_resize` 会话复用列为后续优化)。
- 已知风险:超大图(>6000×3000) tiled 路径从未在本仓库验收过——验证计划第 3 步专门覆盖;若 tile 混合接缝可见,tile 尺寸/重叠(context 128px)已是宿主调好的参数,优先怀疑尺寸非偶对齐而非混合本身。
- 构建陷阱沿用记忆:核对 exe 时间戳;`dotnet build -p:Platform=x64`。
