## 第二次修复：Stage 命令退出码 1（编码坑）

- **根因**：`tools/package.ps1` / `package-msix.ps1` 是 UTF-8 **无 BOM**；VS 的 Stage 用 `powershell.exe`（WinPS 5.1），5.1 按 GBK 解码无 BOM 的 UTF-8 脚本 → 中文注释/字符串乱码并产生 6 / 7 处语法错误 → 脚本一行未执行 → 退出码 1。诊断证据：`artifacts/msix/payload` 时间戳/内容完全未变；用 `[Text.Encoding]::GetEncoding(936).GetString(bytes)` + `Parser::ParseInput` 模拟 5.1 解码可精确复现这些错误。
- 修复：两个脚本改为 UTF-8 with BOM（PS7 同样兼容）；`$OutputRoot.TrimEnd('\','/')` 改为 `$OutputRoot -replace '[\\/]+$',''`；wapproj 注释与 README 明确写入「含中文的 tools/*.ps1 必须带 BOM」。
- **教训**：PS7 默认 UTF-8 读无 BOM 脚本，所以之前用 PS7 工具端到端验证通过并不代表 VS 的 5.1 能跑。凡是被 wapproj 的 `Exec` 调用的脚本，必须用 5.1 实测（可用 `& 'C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe' -File ...`），或用 GBK 解码 + ParseInput 模拟。
- 验证：WinPS 5.1 实跑 `package.ps1 ... -AllowGenericFfmpeg` 退出码 0，中文警告正常，产出完整负载；5.1 模拟解析 0 错误；XML / PS1 语法 / `git diff --check` 通过。
- 现有验证产物（均未删除）：`artifacts/msix/payload`（旧的不完整负载，用户拒绝删除）、`payload-verify`（PS7）、`payload-51check`（5.1），各约 1.7 GB。
